Run these diagnostics against the existing Proteus4 shared library from a private directory.
No engine code is changed by the probe.

g++ -O1 -g0 -std=gnu++17 -pthread trace.cpp \
  -I/home/bruce/devl/Proteus4/SharedBuild \
  -L/home/bruce/devl/Proteus4/SharedBuild \
  -Wl,-rpath,/home/bruce/devl/Proteus4/SharedBuild \
  -lproteusGraph -lgmp -lgmpxx -o trace
./trace definitions.pr state.pr > state.log 2>&1
./trace definitions.pr history.pr > history.log 2>&1
./trace definitions.pr independent.pr > independent.log 2>&1
./trace definitions.pr changed.pr > changed.log 2>&1
./trace definitions.pr spatial.pr > spatial.log 2>&1
python3 verify.py

The program creates a private sessionDB.pr and codeDog.log in its working directory.
These are diagnostic side effects, not changes to the application fixture.
Step IDs are local to each run. Compare assertions and canonical output rather than
assuming generated POV IDs are stable across changes.
Unknown numeric sizes legitimately leave symbolicValues true in these examples.
