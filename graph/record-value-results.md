# Supplied unordered values

An unknown value can acquire a supplied unordered description through the same
independent member views and identities used by list correspondence. Nested
unordered members are supported as values of ordered or unordered lists. Omitted
parts stay open; an explicit size bounds membership, and unknown values retain
subscriptions. Existing copied members keep their POVs as source parts arrive.

`RecordStructure` reads the current members and pairs only existing identities.
`RecordValue` proposes the header/member Sets. It does not choose a positional
or nominal alignment between independently populated unordered descriptions.
Such a correspondence remains pending. Embedded unordered spans and parser-owned
streaming records also remain outside this change. New member creation uses
the existing member-view factory and retains its admission rules.

Explicit identity assertions can connect differently named descriptions;
copying retains a written target name. This does not make those type words
interchangeable in field selection. Alias traversal was moved out of the field
predicate into the definition catalogue and reused by RHS representation proof.
It reads explicit type links without expanding unrelated definition members.
Supplied partial typed descriptions use the same existing exemption from full
parent-definition enforcement when read as RHS payloads.

The shared RHS proof can now check copied unordered members through their
identities. It suppresses redundant rendering only after their supplied facts
are represented. Open or typed work remains searchable, and later publications
invalidate the proof. The graph scheduler is unchanged; this adds no duplicate
adjacency storage and no recursive normalize call.

The original `unordered/seq1` fixture passes unchanged in both Proteus3 and
Proteus4. Nineteen focused cases cover plain/bounded/nested copies, ordered
containers, partial definitions, independent descriptions, late values/parts,
cancellation, size contradictions, source/target names, route cost, replay,
lookup, aliases and incomplete meanings. The original Proteus3 unknown-overlay
probe exits without a summary; only the successful original fixture and the
explicit differently-named description probe are claimed as historical checks.

Completed bounded results reconsider new facts when explicitly normalized again;
open descriptions keep active subscriptions. The late-contradiction test uses
that explicit normalization rather than requiring a completed handle to reopen.
